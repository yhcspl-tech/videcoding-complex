# 굿즈샵 디자인 톤 맞추기

이 사이트의 모든 페이지(`index`, `cart`, `login`, `checkout`, `success`, `fail`, `orders`, `admin`)는
**하나의 사이트처럼** 보여야 한다. 화면을 만들거나 고칠 때 아래 5가지 규칙을 지킨다.

디자인의 기준은 `css/style.css` 한 파일이다. 새 페이지도 이 파일을 그대로 쓰고,
페이지 전용 `<style>` 이나 `style="..."` 인라인 스타일로 색·크기를 새로 만들지 않는다.
필요한 모양이 없으면 `css/style.css` 에 공통 클래스로 추가한다.

**새 페이지는 이 signup.html 을 기반으로 시작할 것.**
- 기본 틀 파일: 이 스킬 폴더의 [signup.html](signup.html) — 공통 헤더(로고 / 메뉴 / 로그인 상태), 공통 푸터(회사 정보 / 약관 링크), 비어 있는 본문 영역
- 사이트 루트 폴더에 복사한 뒤 새 이름으로 바꾸고, `<main>` 안만 채운다. 헤더·푸터·스크립트 순서는 바꾸지 않는다.
- 헤더는 `js/auth.js` 가 자동으로 그리므로 페이지에서 직접 만들지 않는다.

## 금지 규칙 — 어떤 경우에도 하지 않는다

### 금지 1. 이모지·아이콘 사용
- 화면에는 **글자로만** 표시한다. 이모지(🛍️ 🎉 😢 ⚠️ 🧪 등), 아이콘 폰트, 아이콘 그림(SVG·PNG)을 넣지 않는다.
- 제목·버튼·메뉴·안내 문구·결과 화면 어디에도 넣지 않는다.
- 상태를 알릴 때도 그림 대신 글자로 쓴다.
  - 결과 화면: "🎉" 대신 제목 "결제가 완료됐어요"
  - 상태 표시: 배지 글자(`App.statusBadge`: 결제완료 / 결제대기 / 결제실패)
  - 수량 버튼의 "−" "+" 는 기호 글자이므로 허용한다.
- 상품 사진(`products.image_url`)은 아이콘이 아니라 상품 정보이므로 허용한다.

### 금지 2. 페이지마다 다른 색
- 색은 `css/style.css` 의 `:root` 에 정해진 변수만 쓴다. 페이지·스크립트에서 색상 코드(`#ff6600`, `rgb(...)`, `red` 등)를 직접 쓰지 않는다.
- 같은 역할은 모든 페이지에서 같은 색이다.
  - 주요 버튼은 항상 `--primary`, 삭제·오류는 항상 `--danger`, 성공은 항상 `--ok`, 대기·주의는 항상 `--warn`
- 특정 페이지만 배경색·버튼색·글자색을 다르게 바꾸지 않는다 (관리자 페이지 포함).
- 정해진 색으로 표현이 안 될 때만 `:root` 에 변수를 추가하고, 그 변수를 모든 페이지가 같이 쓴다.

### 금지 3. 같은 의미에 다른 단어
- 한 가지 의미에는 **한 단어만** 쓴다. 페이지마다 바꿔 쓰지 않는다.
- 특히 "저장" / "확인" / "완료" 를 섞어 쓰지 않는다. 의미별로 아래처럼 나눠서 고정한다.

| 의미 | 버튼에 쓰는 단어 | 끝난 뒤 알림 | 쓰지 않는 말 |
|---|---|---|---|
| 입력한 내용을 기록 | **저장** | 저장했어요 | 확인, 완료, 등록, 적용 |
| 안내를 읽고 닫거나 질문에 "예" | **확인** | (없음) | 저장, 완료, 예, OK |
| 묻는 창이나 하던 일을 그만두기 | **취소** | (없음) | 닫기, 아니오, 돌아가기 |
| 지우기 | **삭제** | 삭제했어요 | 제거, 지우기, 삭제하기 |

- "완료"는 버튼에 쓰지 않는다. 일이 끝났다는 **알림 문장**에만 쓴다 (예: "결제가 완료됐어요").
- 나머지 단어(장바구니 담기, 결제하기, 결제내역 등)는 5번 규칙의 표를 따른다. 표에 없는 새 의미가 생기면
  단어 하나를 정해 표에 추가한 뒤 모든 페이지에서 그 단어만 쓴다.

## 1. 모든 페이지에서 같은 색 · 같은 버튼 모양

### 색: `:root` 변수만 쓴다
색상 코드(`#3d5af1` 같은 값)를 직접 쓰지 말고 아래 변수를 쓴다.

| 변수 | 용도 |
|---|---|
| `--bg` | 페이지 배경 |
| `--surface` | 카드·표·헤더 배경 (흰색) |
| `--text` | 기본 글자 |
| `--muted` | 보조 글자 (설명, 날짜, 안내) |
| `--line` | 테두리·구분선 |
| `--primary` / `--primary-dark` | 주요 버튼, 강조, 링크 포커스 (파란색) / 눌렀을 때 |
| `--danger` | 삭제·실패·오류 |
| `--ok` | 성공·결제 완료 |
| `--warn` | 대기·주의 |
| `--danger-soft` · `--ok-soft` · `--warn-soft` (+ `-text`) | 메시지·배지의 연한 배경 / 진한 글자 |
| `--hover` · `--chip` · `--img-bg` | 눌렀을 때 배경, 선택된 메뉴·탭 배경, 이미지 자리 |

새 색이 꼭 필요하면 `:root` 에 변수를 먼저 추가하고 그 변수를 쓴다.

- 상태 표시는 새로 만들지 말고 `App.statusBadge(status)` (`.status-paid` / `.status-pending` / `.status-failed`)를 쓴다.
- 안내 메시지는 `.msg.msg-error`(오류) / `.msg.msg-ok`(성공), 잠깐 뜨는 알림은 `App.toast()` 를 쓴다.

### 버튼: 정해진 4가지만 쓴다
| 클래스 | 언제 |
|---|---|
| `.btn` | 그 화면에서 **가장 중요한 동작 1개** (결제하기, 장바구니 담기, 로그인) |
| `.btn.btn-outline` | 보조 동작 (계속 쇼핑하기, 취소, 돌아가기) |
| `.btn.btn-danger` | 되돌릴 수 없는 동작 (삭제, 비우기) — 없으면 `css/style.css` 에 추가 |
| `.btn-block` | 폭을 꽉 채울 때 덧붙임 (폼 제출, 모바일 주요 버튼) |

- 모서리는 버튼·입력칸 `10px`, 카드 `var(--radius)`(14px)로 통일. 다른 값 쓰지 않는다.
- 한 화면에 파란 `.btn` 이 여러 개 경쟁하지 않게 한다. 나머지는 `.btn-outline`.
- `<a>` 로 만든 버튼도 `class="btn"` 을 붙여 모양을 맞춘다.
- 밑줄 텍스트 버튼(예: 장바구니의 `.remove`)은 새로 늘리지 않는다.

## 2. 글씨는 폰에서도 잘 보이게 충분히 크게

- 기본 글자 크기는 **16px(1rem)** — `body` 기본값을 줄이지 않는다.
- **어떤 글자도 14px(0.875rem)보다 작게 만들지 않는다.** 날짜·주문번호·표의 보조 글자 포함.
- 입력칸(`input`, `select`, `textarea`)은 **16px 이상**. 그보다 작으면 아이폰이 화면을 자동 확대해 버린다.
- 가격·합계 같은 중요한 숫자는 굵게(`font-weight: 800`) 하고, 숫자 정렬은 `font-variant-numeric: tabular-nums`.
- 줄 간격은 `line-height: 1.55` 유지. 회색 글자는 `--muted` 만 쓴다 (더 연한 회색은 흰 배경에서 안 읽힌다).

---

## 3. 버튼은 손가락으로 누르기 쉽게 크게

- 누를 수 있는 모든 것(버튼, 링크 버튼, 탭, 수량 +/-, 체크박스 영역)은 **최소 44×44px**.
  - 주요 버튼(`.btn`)은 높이 **48px 이상** (`min-height: 48px`).
  - `.btn-sm` 도 `min-height: 44px` 아래로 내려가지 않게 한다.
- 버튼끼리 붙이지 않는다. 나란히 놓을 때 간격 **8px 이상** (`gap: 10px` 권장).
- 삭제처럼 위험한 버튼은 주요 버튼 바로 옆에 붙여 두지 않는다 (잘못 누르기 쉬움).
- `:hover` 에만 의존하지 않는다 (폰에는 마우스가 없다). 눌렀을 때 상태(`:active`)와
  키보드 포커스(`:focus-visible` 파란 테두리)는 이미 공통 CSS에 있으니 지우지 않는다.
- 처리 중에는 버튼을 `disabled` 로 막고 글자를 바꿔 두 번 눌림을 막는다 (예: "결제하기" → "처리 중…").

---

## 4. 모바일에서 자연스럽게 보이는 반응형

- 모든 HTML `<head>` 에 `<meta name="viewport" content="width=device-width, initial-scale=1">` 가 있어야 한다.
- **화면 나누는 기준은 `@media (max-width: 760px)` 하나.** 새 기준 폭을 만들지 말고
  `css/style.css` 맨 아래 "모바일" 블록에 함께 넣는다.
- 고정 폭(`width: 600px` 등) 대신 `max-width` + `width: 100%` 를 쓴다.
- 여러 칸 배치는 `grid` / `flex` + `flex-wrap: wrap`. 모바일에서는 1칸(목록은 2칸)으로 쌓는다.
  - 이미 있는 패턴: `.grid`(상품 2칸), `.layout-2col`(장바구니 → 1칸), `.stats`(통계 2칸)
- 넓은 표는 `.table-wrap` 으로 감싸 표만 옆으로 스크롤되게 한다. **페이지 전체가 옆으로 밀리면 안 된다.**
- 이미지에는 `max-width: 100%` 와 비율(`aspect-ratio`)을 줘서 찌그러지거나 넘치지 않게 한다.
- 긴 이메일·주문번호는 `word-break: break-all` 또는 말줄임(`text-overflow: ellipsis`)으로 처리.

## 5. 같은 의미는 같은 표현으로

말투는 **부드러운 존댓말 "~해요 / ~할까요? / ~해 주세요"** 로 통일한다.
"~합니다 / ~습니다" 와 섞지 않는다.

### 확인 질문 (`confirm()` 등)
| 상황 | 문구 |
|---|---|
| 삭제 | **삭제할까요?** |
| 장바구니 비우기 | **장바구니를 비울까요?** |
| 로그아웃 | **로그아웃할까요?** |
| 작성 중 나가기 | **작성 중인 내용이 사라져요. 나갈까요?** |

질문 문구는 "~할까요?" 형태로 끝낸다. "정말 삭제하시겠습니까?", "삭제하시겠어요?" 같은 변형 금지.

### 완료 · 안내 · 오류
| 상황 | 문구 |
|---|---|
| 장바구니 담기 | `'상품명'을(를) 장바구니에 담았어요` |
| 삭제 완료 | 삭제했어요 |
| 저장 완료 | 저장했어요 |
| 결제 완료 | 결제가 완료됐어요 |
| 결제 취소 | 결제를 취소했어요 |
| 로그인 필요 | 로그인이 필요해요 |
| 권한 없음 | 관리자만 볼 수 있어요 |
| 비어 있음 | 아직 ○○이(가) 없어요 (예: 장바구니가 비어 있어요, 아직 결제내역이 없어요) |
| 불러오는 중 | 불러오는 중… |
| 처리 중 | 처리 중… |
| 알 수 없는 오류 | 문제가 생겼어요. 잠시 후 다시 시도해 주세요. |
| 입력 오류 | ○○을(를) 확인해 주세요. (예: 이메일 주소를 확인해 주세요.) |

### 버튼 이름 (같은 동작 = 같은 단어)
`장바구니 담기` · `결제하기` · `주문하기` · `삭제` · `취소` · `확인` · `로그인` · `회원가입` · `로그아웃` · `계속 쇼핑하기` · `결제내역 보기`

- "지우기/제거/삭제하기" 대신 **삭제**, "닫기/돌아가기/뒤로" 중 의미가 취소면 **취소**.
- 메뉴 이름은 헤더와 페이지 제목을 같게: **상품 / 장바구니 / 결제내역 / 관리자**.

### 숫자 · 날짜
- 금액은 항상 `App.won(n)` (예: `12,000원`). 직접 `toLocaleString` 하지 않는다.
- 날짜는 항상 `App.formatDate(iso)`.
- 화면에 넣는 사용자 입력·DB 값은 `App.escapeHtml()` 로 감싼다 (프로젝트 규칙).

## 기준 예시 — 모든 페이지는 이 모양을 따른다

### 좋은 버튼
- **손가락으로 편하게 누를 만큼 크게**: 높이 48px 이상 (작은 버튼도 44px 이상)
- **모서리는 부드럽게 둥근 모양**: `border-radius: var(--radius-sm)` (10px)
- **색은 화면에서 가장 잘 보이게**: 그 화면의 가장 중요한 동작 1개에만 파란색 `--primary` + 흰 글자

```html
<!-- 주요 버튼: 화면당 1개 -->
<button class="btn btn-block" type="button">결제하기</button>

<!-- 보조 버튼: 주요 버튼과 나란히 둘 때 -->
<div class="result-actions">
  <a class="btn" href="orders.html">결제내역 보기</a>
  <a class="btn btn-outline" href="index.html">상품 보러 가기</a>
</div>
```

이렇게 하지 않는다:
```html
<button style="background:#ff6600; padding:4px 8px; border-radius:0">결제</button>  <!-- 작고, 각지고, 정해지지 않은 색 -->
<a href="#" style="font-size:12px">결제하기</a>                                  <!-- 버튼이 아니라 작은 글자 링크 -->
```

### 좋은 입력칸
- **입력칸 위에 무엇을 적는 칸인지 라벨 표시**: `<label for="...">` 를 입력칸 바로 위에 둔다.
  placeholder(흐린 안내 글자)만으로 대신하지 않는다 — 글자를 치면 사라져서 무슨 칸인지 잊어버린다.
- **잘못 입력하면 빨간색으로 알려주기**: 그 칸의 테두리를 빨갛게(`aria-invalid="true"`) 하고,
  칸 바로 아래에 빨간 글씨로 무엇이 틀렸는지 적는다(`.field-error`). 고치면 둘 다 없앤다.

```html
<label for="email">이메일</label>
<input id="email" type="email" autocomplete="email" placeholder="you@example.com"
       aria-invalid="true" aria-describedby="email-error">
<p id="email-error" class="field-error">이메일 주소를 확인해 주세요.</p>
```

```js
// 틀렸을 때
emailEl.setAttribute("aria-invalid", "true");
errorEl.textContent = "이메일 주소를 확인해 주세요.";
errorEl.classList.remove("hidden");
// 고쳤을 때
emailEl.removeAttribute("aria-invalid");
errorEl.classList.add("hidden");
```

- 빨간 테두리·빨간 글씨 모양은 `css/style.css` 에 이미 있다 (`input[aria-invalid="true"]`, `.field-error`). 새로 만들지 않는다.
- 오류 문구는 5번 규칙의 "○○을(를) 확인해 주세요." 형태를 쓴다.
- 폼 전체에 대한 결과(로그인 실패 등)는 기존처럼 폼 아래 `.msg.msg-error` 로 보여 준다.

## 작업 순서

0. 새 페이지라면 이 스킬 폴더의 `signup.html` 을 사이트 루트에 복사해서 시작한다.
1. 고칠 페이지와 `css/style.css` 를 먼저 읽고, 이미 있는 클래스를 재사용할 수 있는지 본다.
2. 위 5개 규칙에 맞춰 만들거나 고친다. 새 모양이 필요하면 `css/style.css` 에 공통 클래스로 추가한다.
3. 문구를 바꿨다면 같은 의미의 다른 문구가 남아 있지 않은지 검색한다
   (예: `grep -rn "삭제하시\|습니다" js *.html`).
4. **직접 확인한다**: 로컬 서버(`http://localhost:8000/`)로 열어서
   - 폭 **375px**(폰)과 **1280px**(PC) 두 가지로 본다.
   - 가로 스크롤이 생기지 않는지, 글자가 14px 미만인 곳이 없는지, 버튼이 44px 이상인지 확인한다.
   - 다른 페이지와 나란히 놓고 색·버튼·말투가 같아 보이는지 비교한다.
5. 이슈가 나오면 고치고 4번을 다시 한다. 마지막에 확인한 것과 못 확인한 것을 보고한다.

## 점검표 (끝내기 전에)
- [ ] 이모지·아이콘이 하나도 없다 (금지 1)
- [ ] 페이지마다 색이 다르지 않고 `:root` 변수만 썼다 (금지 2)
- [ ] 같은 의미에 다른 단어를 쓰지 않았다 — 특히 저장/확인/완료 (금지 3)
- [ ] 색상 코드를 직접 쓰지 않고 `var(--...)` 만 썼다
- [ ] 버튼은 `.btn` / `.btn-outline` / `.btn-danger` (+`.btn-block`) 중 하나다
- [ ] 14px보다 작은 글자, 16px보다 작은 입력칸이 없다
- [ ] 누르는 것은 모두 44px 이상, 주요 버튼은 48px 이상이다
- [ ] 375px 폭에서 가로 스크롤이 없다
- [ ] 문구가 "~해요 / ~할까요?" 말투이고 위 표와 같은 표현이다
